MIGRATION REQUIRED BEFORE USING THIS VERSION

The order-integrity update adds:
- core.0019_order_item_consumption: per-order-line ingredient consumption snapshots
  and a flag distinguishing older orders.
- accounting.0004_journalentry_adjustment_source: a journal source label for
  order adjustments.
- core.0020_expense_is_voided_expense_voided_at: keeps voided expenses for audit
  while excluding them from operating expense reports.

Back up the production database before deploying. The Render build script runs
`python manage.py migrate` automatically. Confirm that the deployment migration
succeeds before using the POS.

Existing orders are not retroactively assigned per-item consumption snapshots.
Their quantities cannot be edited safely, because recipes may have changed.
Voiding an older order uses its historical stock logs when those records exist.
If the log is incomplete, the operation stops for manual reconciliation.
Previously edited or deleted expenses may already have mismatched accounting
entries; this migration does not reconstruct those historical transactions.
